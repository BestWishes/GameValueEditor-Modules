# 再刷一把：远征 · 全部堆叠材料数量设计

## 授权与边界

用户请求“把所有材料的数量都做成能修改的”。本轮实现当前精确 0.116.70、存档格式 38、远征模式的材料实时读取与任意合法目标数量设置，不再限定保护卷 2↔3。不开发独立窗口/测试游戏副本，不控制屏幕，不提交/发布，不创建新备份，复用并保留旧备份；不将旧完整存档覆盖当前进度。

交付范围为可直接连接原游戏的参数化实时读写后端和受控驱动，不是正式模块页面或发行包。正式页面/目录接入不在本轮伪称完成。实现不会替用户任意决定 29 项目标数量并把整张材料表同时改掉。

## 完整字段清单与证据

纯 Engine/配置在匹配 Electron 44.2.0、Node 24.20.0 x64 的独立无窗口进程核验；没有加载 main/preload、打开原 profile 或连接游戏。

当前默认 Engine 定义 24 个 materials 字段；旧备份经本构建 Engine 重载保留另外 3 个通行证字段，共 27 个。材料面板还显示根 tickets 与 abyss.tickets，因此包含共 29 个堆叠数量字段。配置和限定材料面板字节码常量用于核对中文名，不把相似字段自动变成可写字段。

所有字段均通过 0、1、1,000,000,000 构造器重载探针。24 个默认材料及两种 tickets 拒绝负数、小数与 1,000,000,001；三个额外通行证在纯 Engine 中有更宽松的反序列化行为，编辑器仍采用保守的 0～1,000,000,000 整数限制，绝不据此开放负数。另核验 enhance-gems 的两种强化宝石配置 limit=9999，因此灵魂宝石/创造宝石实际编辑上限进一步收紧为 9999；不把纯存档格式接受十亿当成游戏购买/使用上限。

材料叶子键：stones、immortalShards、adsorptionStones、synthesisProtectionScrolls、advancedRecruitTickets、costumeTickets、flameKeys、cowTickets、tkRicePass、tkHeishanPass、tkLiangzhouPass、tkChangshaPass、tkJiaozhouPass、tkLiaodongPass、tkShuhanPass、tkDongwuPass、tkSoulPass、tkHulaoPass、tkTongquePass、tkHuarongPass、mythicGems、protectionScrolls、sacredProtectionScrolls、fusion、soulGems、creationGems、wheelTickets；额外的两个语义 ID 为 recruitTickets、abyssTickets。

金币不是材料数量，人物碎片属于人物成长；装备、矿石、镶嵌宝石是独立 UID 集合，不能修改一个总数或复制 UID。三国模式及其额外制造材料/马草尚未验证，明确拒绝，不借“全部材料”开放别的游戏模式。

## 读写契约

1. 固定源码工厂只支持 catalog/list/set；用户参数只允许语义 materialId 与整数数量，没有任意表达式/对象路径接口。
2. catalog 离线列出定义；list 不调用 serialize/save/flush，不变更全局变量。列出 0 数量；缺失、访问器、不可写、存储数量不一致、非法数量只读并给出原因。额外未知材料显示为只读未知项，禁止自动加入白名单。
3. 原进程组重新发现，核对启动实例、EXE/ASAR 哈希、匹配运行时、原 package/profile、唯一游戏窗口、世界 999 和隔离设置。必须由用户启动时显式开启只绑定 127.0.0.1 的 inspector；没有端口则提示，不强行启用。不使用旧禁用路线。
4. list 返回有限数量/状态与 scope 摘要；读回执绑定进程启动实例、构建、存档槽位及保守角色/物品身份摘要，set 必须用回执的旧值。不能把不同存档的相同数量视为同一个对象。允许唯一识别的远征主档及 1～4 槽位，歧义拒绝。
5. set 必须在 idle、同一同步 renderer 调度里重新取得完整当前快照并提交，核对旧值、存档身份、对象/平台引用。不会复用跨帧快照、忽略 offline.lastActiveAt 或持有堆地址。
6. 同值返回 unchanged，不调用 serialize、save 或 flush。缺失字段不是“未拥有”，不会凭猜测创建属性；正常 Engine 已定义的 0 数量可修改。
7. 改一叶子，serialize 后将目标叶子规范化回旧值，要求整个 JSON 与修改前完全一致。保存前失败，只在仍是自己改过的同一叶子时恢复；不得覆盖换档后的对象。
8. 原生 platform.save 必须同步 true；完整 origin 主档、原生 read、当前序列化及其他主槽核验一致。flush 只是请求，不等于重启持久化。保存开始后任何不确定结果都不自动恢复/重试。
9. 驱动持有同会话写入互斥锁，在发送前持久记录 pending。回执与同一 requestId 防重放；保存失败、消息丢失、超时、会话变化保留不确定屏障，禁止继续写入同一会话。只读仍可用。正常重启的新实例必须重新读取回执，不沿用旧数量。
10. 不写原 LevelDB、不补丁 ASAR、不操作 Steam/排行榜，不关闭 inspector 服务，只正常关闭客户端连接。全部存档正文只在内存中使用，日志仅存摘要/数量，不新建完整快照。

## 实施与验证顺序

1. 新增独立 all-materials runtime，保留旧 2↔3 试验及禁用代码不变。
2. 新增固定 controller 与 List/Set 驱动；无任意代码入口、固定构建检查、参数验证、错误/超时/防重放。
3. 单元测试逐项覆盖 29 个字段的 0、中间值、上限、恢复和同值；覆盖换实例、错误格式/模式/槽位、缺失/访问器、只读、未知字段、全存档差异、保存不确定和数据保密。
4. 使用当前游戏纯 Engine 和旧备份副本，对 29 项分别做设值、完整单字段差异、构造器重载及恢复；不打开正在使用的存档。
5. 只有用户启动入口可用时再做实时只读清单。小值实时修改需要明确目标和用户画面/正常重启观察，不能将离线测试写成 29 项实机闭环。
6. 同步 README/设计/接入研究，记录实现、自动验证与尚待实机证据的区别。

## 编码前设计检查 3 遍

1. 覆盖/方向：对照默认定义、旧备份本构建重载、材料面板定位 27+2；数量字段与 UID 集合明确区分，非远征模式安全拒绝。不是猜整数扫描，也不是为每种材料造重复工具。
2. 安全/竞态：完整比较保持在同步调度；参数、旧值、scope、启动实例、构建、槽位、phase、叶子描述符都检查；同值零写、缺失不造、保存后不自动回退、未知结果停写。
3. 验证/交付：29 项逐项纯 Engine 重载与恢复只是离线契约证据；真实端点、画面和重启结果单独记录。当前原游戏未开调试参数，不强行接入；没有正式模块页面，不承诺 29 项实机已验收。

## 源码检查 3 遍和验证结果

1. 数据/交易：29 项分别覆盖 0、17、各自上限、恢复、同值不序列化/不保存；未知键、路径、访问器、只读、类型/范围异常、版本/模式/槽位/身份变化拒绝。完整 inventory/offline/luckyWheel 变化拒绝，保存前只恢复同一叶子；保存后不确定不回退。补上读取/保存前 API 调用之后的再次实例检查，防止调用副作用造成迟到通过。
2. 接入/控制：固定源码按 JSON 参数组装，无任意表达式；控制器模拟真实原生隔离调度，跨帧 offline 更新仍完整保留，同调度捕获/提交。同值无 flush；未知状态、原 profile/package/运行时/隔离变化拒绝。驱动有启动时刻与进程/包指纹、5 分钟回执、loopback 所有者、单次发送、永久 requestId、互斥锁及持久 pending/uncertain 屏障；成功结果核对目标、旧值、槽位、旅程和 scope。主存档正文仅内存中哈希，不写日志。
3. 真实引擎/回归/证据：本构建纯 Engine 对 29 项分别执行 0、1、17、上限及恢复/构造器重载，116 个目标案例通过；每步完整其他存档数据与另一个主槽保持不变，旧 fixture 哈希未变。全套原有和新增测试最终 220 项通过；PowerShell 语法与组装 Node 表达式编译通过；原有主程序未提交变更不触碰，旧禁用驱动不变，既有 13 个备份文件哈希仍匹配。
