## 只读研究结论

原 ASAR 哈希仍为 5A4F4E414BD06FC248CFE2AD30E7D9EE3B110968DB888FDB733CD57F78A6B294，Electron 44.2.0 / Node 24.20.0 x64。源码为 Bytenode；只在匹配运行时的无窗口独立进程调用纯 Engine/配置，不加载 main/preload、原 profile 或原游戏存档。旧存档副本只作离线结构 fixture，不回写原进度。

转盘是 16 格：原生 wheelWeights 按普通、不朽、神话、装备保护卷、神圣装备保护卷分配权重，再由 chooseWheelIndex 按总权重归一化抽取。额外奖励为 rollWheelBonus 的 double（原 2%）和 marquee（原 1%）两类，剩余 97% 无额外奖励。它们与奖格抽取分开。一次 spin 已实际创建奖励并扣转盘币，finish 不是“抽取但尚未到账”，故助手不能调用 spin/finish 做原存档测试。

掉落不是一个字段：普通装备使用 dropBonus 等原生加成；守关胜利有独立 50% 深渊券判定；深渊不朽由 immortalDropChance 加保底控制。概率说明明确装备掉落加成不影响入场券。纯引擎已追到实际新增 UID、材料增量和结算分支；不得用库存末尾旧物品或只读 getter 代替新掉落效果。

## 概率参数与边界

| 参数组 | 表达方式 | 保留的游戏规则 |
| --- | --- | --- |
| 转盘五类奖励 | 五类百分比分配，合计 100%；类内可按奖励类型/品质权重调整 | 原奖池、16 格、消耗、背包容量、物品创建与 UID |
| 转盘额外奖励 | double / marquee 百分比，合计不超过 100% | 原生奖励数量与创建/结算路径，不把名称猜成物品升级 |
| 装备额外掉落加成 | 原规则基础上额外 −100～+100 个百分点 | 原基础概率、角色/装备加成、必掉规则；不是“最终掉率百分比” |
| 深渊不朽随机概率 | 0～100% | 原生保底、掉落池、容量、词条与收益结算 |
| 守关深渊券概率 | 0～100% | 普通招募券等奖励不变，不覆盖已获得的券 |
| 火焰王座不朽/神话池 | 分别 0～100%，针对原池中每件装备的独立判定 | 原池、条件、背包容量、物品创建；不是互斥总和 100% |

对采矿、奶牛关、其他神话专属掉落、离线收益等继续逐一核验来源；尚未证明的分支不挂一个“通用爆率”伪称支持。概率不会凭猜测写进现有存档；本轮为进程会话内规则，重启恢复原规则，可显式手动还原。已产生的正常抽奖/战斗收益仍由游戏自身保存，不用旧完整存档撤销。

## 实施设计

1. 独立纯概率模型：校验有限数字、百分比总和、权重范围/可用奖励；输出每格归一化概率，明确权重不等于百分比。CDF 映射保留一次原生随机调用，仅改变目标判定。
2. 单个引擎的可还原会话：固定语义控制项，绑定 game/engine/state/platform/原存档身份；只包装已验证的转盘、胜利判定及概率 getter。不得改全局 Math.random，不改 ASAR，不改物品/数量/价格，不调用抽奖、战斗或保存。
3. 安全范围：只有原隔离世界、精确构建及已进入的远征存档可操作；配置/还原要求 idle、无转盘 pending。即时调用中临时接管该引擎 rng，finally 还原；其他随机用途透传，未知调用位置不映射。存档换档或钩子冲突后停用并报告，不覆盖第三方函数，不向游戏抛新错误。
4. 固定请求控制器和受控驱动：复用原入口、loopback 所有者、实例/指纹、回执、互斥与单次请求/不确定屏障原则；日志不包含完整存档。只配置概率，不代替用户消耗资源测试。
5. 先做纯模型测试和精确原生引擎对照，包括 0/100%、中间分布、默认透传、不同奖盘、正常奖励结算/新 UID、保底、原字段不变、钩子还原与异常；再由用户开启接口，先只读核验，明确测试参数和观察步骤。
6. 同步文档，区分参数实现、纯引擎行为证据、实机证据和仍未适配分支；不伪称所有爆率已完成。

## 编码前检查三遍

1. 方向/语义：奖格概率、额外奖励、装备加成、深渊随机和保底、门票概率分开。五类奖盘有缺类时不得把不存在的奖品造出来；类内权重先归一化。材料数量控制保持独立。
2. 安全/所有权：不使用全局随机、不强行启用调试、不代用户抽奖、不覆盖旧快照；只绑定精确构建和原存档实例。还原只撤销本模块拥有的函数，结果不确定不重试。配置不能写游戏存档。
3. 验证/交付：使用新 UID 识别新奖励，不能看旧库存尾项；证明原生结算使用调整后的概率，不能只看 getter。未知分支和未知版本拒绝；无正式页面/发行承诺，实机阶段仍需用户观察。
