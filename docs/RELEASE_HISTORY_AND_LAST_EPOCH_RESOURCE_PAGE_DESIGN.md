# Release 历史与 Last Epoch 资源页实施约束

本文件是主程序 `docs/RELEASE_RETENTION_ROLLBACK_AND_MODULE_VISUAL_DESIGN.md` 在模块仓库的执行约束。

## 目录与发布

- `catalog.json` 使用 Schema 5；每个模块顶层仍描述最新版，并新增按版本降序排列、最多 3 项的 `releases`。
- 每个 release 快照必须携带自己的 Host API、最低主程序版本、可选最高主程序版本、构建兼容信息、编辑器清单、下载 URL、资产字节数和 SHA-256。
- `Publish-GameModule.ps1 -CatalogOnly` 只能使用已远端核验的本地 ZIP，把旧顶层版本转入历史、加入新版本、按数值版本排序并截取 3 项。
- GitHub Release 上传、验证和清理必须使用仓库内正式脚本，不再依赖临时工作区脚本。
- 发布完成且公开目录验证后，按游戏标签前缀保留最新 3 个 Release；只删除超额 Release，不删除 Git 标签。
- 最终模块 DLL 的 `ProductVersion` 提交号必须等于 annotated tag 指向的源码提交。

## 手动回退所需数据

宿主使用版本快照筛选严格低于本地版本的最高兼容版本。兼容必须同时满足当前主程序版本范围、Host API 和游戏构建。模块目录不得提供自动降级指令；只有用户在宿主点击回退后才能下载旧资产。

模块包内 `module.json` 同步声明 `minimumHostVersion` 和可选 `maximumHostVersion`，安装时必须与目录快照一致。版本号仍各自独立；对应关系由这些字段建立，不能靠主程序版本号和模块版本号相等来推断。

现有三组历史包已经核验为 Host API 4 和 6，因此目录迁移时分别写入最低主程序 `0.4.1` 和 `0.4.3`；新 Host API 7 包写入 `0.4.4`。脚本不得为无法由已发布标签确认的旧 API 猜测最低版本。

主程序回退前会检查当前已安装模块是否支持目标主程序。若不支持，宿主只提示用户先手动回退对应模块，不得自动降级模块。

Host API 6 及以上模块替换后必须等待宿主重启再启用。当前进程释放页面并停用该模块，不能为了即时生效重复加载不可卸载的 WPF 上下文。

## 视觉边界

- 模块可以自由实现页面结构，但只能使用宿主提供的主题资源键、控件样式和间距常量。
- 禁止硬编码颜色、覆盖 `Application.Current.Resources`、合并自有全局主题字典或创建自有窗口外壳。
- 共享代码只提供生命周期和可选基础控件，不把整页结构变成宿主协议。

## Last Epoch 资源页

- 新建 Last Epoch 专属资源页面，不再实例化通用 `EntityEditorPage`。
- 分类直接来自现有数据的 `Summary`，当前顺序为 `词缀碎片`、`符文与雕文`、`副本钥匙`。
- 不提供“全部”分类。
- 顶部分类切换，下方单张表格展示该分类所有资源；每一行直接显示名称、数量和状态。
- 修改和保存字段针对表格选中行；未拥有资源保持显示为 0。
- 不修改资源读取、写入、保存、回读和构建兼容逻辑。

## 三轮设计审查记录

1. 方向审查：通过。目录保留每模块最新 3 个版本；只提供显式手动回退；模块页面结构自由、视觉由宿主统一；Last Epoch 资源页与现有三类数据语义一致。
2. 兼容与生命周期审查：通过并补正。快照增加资产字节数；旧 API 4/6 的最低宿主版本来自已发布标签；API 6 及以上替换后停用并等待手动重启，禁止同进程加载两版 WPF 模块。
3. 发布与可验证性审查：通过。三个模块独立递增为 `2.1.2`、`1.3.2`、`0.5.2`；从干净提交重建、核对 DLL 提交号、远端哈希和公开 Schema 5 目录后才运行按标签前缀分组的保留 3 个清理。本次每组最终正好 3 个，不删除已有 Release。

## 三轮实现复核记录

1. 页面与兼容契约复核：通过。三个包均声明 API 7 与最低主程序 `0.4.4`；Last Epoch 资源页由模块单独实现，只有顶部三个现有分类和下方单张表格，没有“全部”或左侧列表；模块候选的主程序范围、Host API 与游戏构建都由宿主同时筛选。
2. 构建与规则复核：通过并修正验证包装层。SDK 与三个模块 Release 构建零警告；模块/目录 Schema、PowerShell 语法、SDK 同步和视觉所有权检查通过；保留 0–5 个版本的分组模拟通过，PowerShell 子脚本依靠异常传播而不误读空 `$LASTEXITCODE`，并确认未知旧 API 不推断最低主程序版本。
3. 发布脚本复核：通过并加固。最终包只能从干净提交构建，DLL 提交号必须等于 `HEAD`；模块发布助手同时核对包内 ID、版本、Host API、最低和最高主程序版本；远端资产验证后才允许 `-CatalogOnly` 写入已有 ZIP 的大小/SHA-256；已发布版本复验只读取原始 ZIP 并核对目录大小/哈希，禁止清空目录后重新打包；公开目录复核后才按游戏前缀清理第 4 个及更旧 Release。

## v0.5.3 未登记构建验证补充

- Last Epoch `v0.5.3` 登记 `1.5.1.4` / Steam Build `25711439` 的精确三文件指纹，并在只读实机测试通过后声明 `supportsUnlistedBuildValidation=true`。
- 该可选字段同步存在于包内清单、目录顶层和对应 release 快照；普通模块缺失时按 `false` 处理。目录 Schema 保持 5，旧主程序忽略字段并继续只接受精确构建。
- 新主程序只有在所有精确候选均不存在时，才允许下载声明该能力的最新版本。下载后仍由模块 `Supports` 执行只读语义校验；失败时不创建页面。未知构建不产生手动回退目标。
- 本次 Last Epoch 版本从 `0.5.2` 递增到 `0.5.3`，Host API 仍为 7，最低主程序仍为 `0.4.4`。

## v0.5.4 运行边界修正

保留 v0.5.3 的发布历史，但不再仅凭 IL2CPP 符号存在接受未知构建。Last Epoch 的资源、异界与摄像头仍有固定布局，整个模块仅接受包内同一条完整三文件指纹记录，并在全部运行时入口核对实际进程身份与文件。未知构建可下载并查看只读拒绝诊断，不能启用或产生猜测回退目标。当前四条构建记录、Host API 7 与最低主程序 0.4.4 不变。

主程序 v0.4.6 同时约束异步操作上下文、加载器进程期待重启 ID，以及更新失败后二次恢复失败的备份保留与显式恢复；仍不提供自动版本回退。详细设计与三轮检查记录位于主程序仓库 `docs/COMPATIBILITY_ASYNC_LIFECYCLE_AND_RECOVERY_FIX_DESIGN.md`。
