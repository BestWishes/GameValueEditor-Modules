# Host API 6 模块页面迁移说明

主程序 v0.5.1 和对应新模块正式提供 Host API 8 协调写入及整页快照，见[当前扩展规范](MODULE_EXTENSION_GUIDE.md)。页面布局仍由模块决定，数据操作通过宿主桥接；以下保持 API 6 当时的设计与发布证据，不表示公开旧包已具有同一套新能力。

后续 API 8 草案补充宿主整页快照能力，协调写入期间的旧读取/错误不应用；模块仍决定如何读取和呈现数据，但通过快照回调提交读取及同步页面应用。这里的 API 6 历史描述不作为当前读取能力约定。

本仓库按主程序的 `docs/HOST_API6_MODULE_PAGES_AND_VERSIONING_DESIGN.md` 实施 Host API 6。设计已经过方向边界、兼容与生命周期、版本与发布三轮评审。

核心决定：游戏页面由游戏模块直接创建并拥有。模块不再向宿主提交 `Kind`/`Role` 让宿主套固定模板；宿主只提供导航容器、主题、生命周期和通用弹框/保存字段服务。旧 API 2 到 5 的模板协议只作为兼容路径保留。

本次迁移范围：

- `game.fzzml`：模块自有背包页、人物属性页。
- `game.worldapart`：模块自有背包页、人物属性页。
- `game.last-epoch`：模块自有人物属性、装备、资源、异界进度、世界功能页。
- 三个模块保持现有稳定模块 ID、编辑器 ID、语义字段键、构建指纹及写入/保存链路。
- 清单 Schema 4 的编辑器元数据删除 `kind`；Host API 提升到 6。
- 模块发布版本各自从自己的最新正式标签加 `0.0.1`，不跟随主程序或其他模块。

实施完成前必须验证真实 ZIP 只包含 DLL 与 `module.json`，由当前宿主创建模块程序集内的 WPF 页面，并在断开/重载后取消和释放页面。WPF 会缓存页面类型，因此 API 6 的独立影子加载上下文保留到进程退出；验证目标是安装源包可立即删除，影子目录由下一次启动清理，不再虚构进程内完全卸载能力。

实现后已完成三轮审查：静态边界确认宿主无游戏专属分支且两仓 SDK 一致；Release 构建与三个真实包加载确认 9 个页面来自模块程序集、安装源包可删除；发布审计确认三个模块分别只前进一个版本且目录在 Release 前未修改。详细记录与最终包哈希见主程序设计文档。

正式标签和 Release 创建后，使用 `./scripts/verify-release.ps1 -VerifyReleasedVersions` 复验目录、真实 ZIP 和宿主加载。这个入口只用于复验当前清单已经对应的正式标签，常规发布前验证仍拒绝重复标签。
