# 装备满值的大转盘路径补齐（本地 0.0.9）

## 原因与范围

0.0.8 包装 `Engine.makeItem` 时只临时替换 `engine.rng`。当前游戏 0.116.92 的大转盘通过 `createRewardItem` 调用相同装备公式，但第四参数同时包含 `rng` 与 `preview`。原生生成优先使用显式 `options.rng`，因此绕过默认 RNG 包装；并非 preview 布尔值阻止生效。原生隔离副本中单抽和十连均复现，双值词条的 4/2 没有取到合法上限 5/3。

本轮只补齐装备生成的显式随机入口，继续使用现有“装备”页开关，不新增选项，不修改主程序业务或公共 API，不改已存在装备、转盘选奖概率、材料消耗或原生发奖规则。交付完整本地离线包，不提交、上传或修改 catalog。

## 详细方案

1. 根据本次 makeItem 是否实际提供函数类型的 `options.rng` 选择原生随机源。显式函数只通过本次调用的浅拷贝 options 包装，保留原参数对象、描述符和其它字段；默认路径仍暂时包装 engine.rng。每次先消耗原函数一次，保留接收者与参数，仅在当前隔离原生代码发现的词条数值消费点返回最大合法随机值。
2. 不改变其它随机消费，不替换全局随机数或原型。finally 恢复默认 RNG；显式路径不写 engine.rng，不留下包装函数。保留所有异常，不能把失败冒充完成或重发业务操作。
3. 给装备会话实现增加内部代际标识。已经应用 0.0.8 规则的原游戏仍可用新页面“恢复原规则”；不能悄悄叠加新旧包装或在刷新时改写已应用规则。恢复后下一次刷新建立新版未安装会话，再由用户应用。旧会话没有安装规则时可无写入地更新注册表；其它概率页面不受影响。
4. 回归覆盖显式函数接收者/参数、冻结 options、不改变调用参数对象、非函数覆盖回退、原生异常、外部 RNG 接管、旧会话迁移及其它命名空间。原生验证直接走 spinLuckyWheel 发奖，核对单抽/十连与无额外奖励/双倍/跑马灯每件武器防具 value/value2、类型/数量/品质、扣币、原有装备和序列化重载。纯引擎与当前实际 renderer 内的副本分别验证，不在原角色上抽奖。
5. 模块清单与 DLL 递增为 0.0.9，宿主保持 0.5.2。复用现有完整离线打包工具、冻结回执和实际模块加载/启动检查。打包工具内部仍使用 local-review 名称，完成验证后仅把 ZIP 以原字节移动到短名称，再用同一工具 VerifyOnly 核验；不改工具或主程序。`GameValueEditor-v0.5.2-202610112.zip` 已为用户保留的 0.0.8 包，新输出为 `GameValueEditor-v0.5.2-202610113.zip`，不覆盖旧包。

## 写代码前的三遍检查

1. 方向：相同原公式缺一条随机输入，不新增另一套装备算法；默认及显式入口共用现有开关，保持模块隔离。
2. 调用与生命周期：原函数只调用一次，随机次数不变，冻结 options 可用，调用结束没有共享残留；旧已应用规则只能主动恢复，不能叠加或自动回退。
3. 证据与交付：必须断言实际奖励实例的数值上限与重载，而非只断言页面共存。保留其它游戏模块及旧短名包，短名不改变包内容、LocalOnly 标识或冻结证据。
