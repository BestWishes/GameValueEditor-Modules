# 新生成装备、宝石、时装与徽章满值（本地 0.1.0）

后续用户反馈暴露本轮遗漏：当时的 gem 检查只覆盖附加词条，独立基础加成 bonus 被作为不变字段，不能将本记录的“满值”证据扩展到 bonus。0.1.1 已增加十类宝石基础属性检查与补修，最新行为见 [宝石基础属性记录](GEM_BASE_LOCAL.md)；本记录保留当时实际范围与旧包。

## 范围与方案

用户要求四类物品统一采用新生成时取满值，已有物品不变；仅交付完整离线包，不提交、不推送、不发布。主程序 0.5.2/API 8 不变，模块计数器 0.0.9 进位为 0.1.0；保留五页和稳定编辑器 ID，在“装备”页扩充既有开关。

原生路径分别为武器防具 `makeItem`、宝石 `makeGem`（打磨/转盘）、时装 `rollCostume`、徽章 `rollBadge`（商城/转盘）。不是在库存里扫描已有物品再改数值，也不把品质、词条选型、变异选择或颜色的随机数一起改成最大。

1. 读入当前包的纯词条定义。通过当前 renderer Engine 的内存隔离副本发现数值调用位置，不沿用旧 bundle 行列号。徽章/时装对单个随机调用做端点比较，只接受原始物品中仅 affixes[].value/value2 增加而其它字段不变的位置。彩色时装另探查变异词条值，固定效果不强改。
2. 保留武器防具的 makeItem 显式 RNG 包装（大转盘传入捕获的源）；其它三类在当前 Engine 的随机源上增加模块所有的轻量映射，只在发现的工厂数值位置生效。宝石共享原生 rollAffix/roll 数值公式，但必须有 makeGem 生成栈，不能影响其他调用。
3. 原随机函数每次仍调用一次，保留 this/参数/消耗次数；数字随机端点交给游戏原公式计算。没有 Math.random/全局原型修改，没有原生工厂/存档文件覆盖。
4. 概率编辑器在每次原生动作前捕获当前随机源，识别本模块的生成映射标记和原始源；临时概率包装在 finally 恢复本次捕获的源。仅承认本模块同 Engine 的映射，不接受任意第三方替换。这样应用/恢复顺序独立，不覆盖掉落、大转盘或命格设置。
5. 新生成映射恢复只卸载自己拥有的 RNG 与 makeItem。已结算奖励保留，未来物品恢复原生随机。旧已应用会话仍可恢复；升级旧概率控制器时维持原有“先恢复、再刷新”合同，不偷偷清空其它页设置。
6. 新增固定只读 probe：在隔离副本核验商城单次/批量、各品质宝石打磨、转盘单次/十连和双倍/特殊额外奖励。比较数值以外的原始物品、消耗、RNG 次数、已有物品、保存重载与分开恢复。固定 `gear/shop/wheel` 三组请求分开执行，避免大矩阵占用一次请求超过原有 15 秒限制；不接受任意脚本、方法或对象路径。原游戏只读接入只运行这些副本，不抽奖、不购买、不打磨、不调用保存。

发现结果只缓存在模块工厂自己的 WeakMap，按当前 Engine 构造器、ASAR 路径和三个原生方法身份复用，不挂到游戏原型或宿主。生成随机映射仅在命中的数值调用处检查当前存档，普通随机调用不重复读取保存状态；原随机调用仍只消费一次。

## 编码前检查（三遍）

1. **语义与原生公式**：实际包 0.116.92 的原生工厂确认分开；徽章值随机与羁绊选型不是同一调用，时装的颜色/品质/变异选型与值调用分别存在；宝石打磨入口参数为 tier/quality，不是库存 UID。隔离脚本已确认这些差异；不使用错误猜测签名。
2. **作用域与共存**：只操作当前 Engine、当前工厂的已发现数值位置；全局随机、品质概率、旧物品、原角色操作和文件不在范围。概率会话必须识别拥有者与原始源，并按动作恢复捕获源，避免原先永久捕获 RNG 导致生成开关应用后冲突。
3. **升级与交付**：检查旧 hook 保留恢复路径、配置原子性和冲突不覆盖；新页文案说明四类新物品，版本同步 0.1.0，宿主/其余游戏模块不修改。隔离消费者、回归、页面与完整包验证通过后才输出新的短文件名，不覆盖先前离线包。
