# 再刷一把：远征 0.0.7 发布记录

## 授权与范围

2026-10-11，用户收到宝石基础属性补修的完整离线包 `GameValueEditor-v0.5.2-202610115.zip` 后授权“可以提交和发布”。本次仅提交此前用户要求的远征十连抽、命格及新生成装备/宝石/时装/徽章满值功能与相关源码、测试、文档。主程序 0.5.2、SDK 和另外三个游戏模块不修改、不重新发布。

线上最后正式标签是 0.0.6；本次按正式发布计数加 0.0.1，发布为 0.0.7。此前 0.0.7～0.1.1 是未发布的本地测试迭代，保留其历史文件与证据，不伪造这些版本的正式标签，也不覆盖旧资产。最后本地版功能全部包含在本次正式版中。

## 发布详细方案

1. 核对当前工作树、远端 main、模块标签及公开 Release；确认只包含远征改动，清单/项目版本一起同步，稳定模块及五编辑器 ID、Host API 8 和最低主程序 0.5.2 不变。
2. 重跑模块源码/主题/目录与发行工具回归、全部远征 Node 和 C# 测试；构建模块仓库各项目。不重复抽奖、消费材料或写玩家存档；游戏消费者沿用上一轮实际原生隔离副本证据，不把静态验证冒充玩家画面测试。
3. 提交验证过的源码，从干净提交使用现有通用 Publish-GameModule 脚本生成正式 ZIP。输出到新建的本轮目录，避免该脚本的旧包清理影响历史文件；核对精确两文件、真实贡献者、DLL 提交来源、版本与实际宿主的五页面加载。
4. 远征带注释标签指向构建提交，推送源码与标签，通过现有代理上传不可变模块 ZIP；独立 VerifyOnly 核验远端大小、SHA-256 和标签，不上传完整离线包。
5. 仅线上资产验证成功后用 CatalogOnly 更新模块目录，独立提交、推送，再读取公开目录核对。只修改远征条目，保留最多三个正式版本；先预演再执行本模块 Release 保留策略，不删除 Git 标签或本地旧包。
6. 使用原正式主程序 ZIP、其余三个原正式模块 ZIP 和新远征正式 ZIP 生成新短名完整离线包，实际验证 DLL、页面与 EXE 启动，再 VerifyOnly；保留用户测试过的旧包和冻结收据。记录正式资产摘要、提交与全部后续处理结果。

## 发布方案复核（三遍）

1. **需求与边界**：五内容页不混淆；修改的是新生成物品数值，不回写旧装备；宝石独立 bonus 有十类真实消费者覆盖。主程序不增加游戏专用代码，小版本仍按名称与当前接口定位，不重新加历史哈希整包门槛。
2. **来源与版本**：先源提交，再干净构建，正式标签与 DLL 源提交一致；版本以最后正式标签递增，本地包不冒充正式版。资产先验证，再目录；不改未发布内容去适配过期断言，不伪造贡献者或重复发布其它游戏。
3. **恢复与保留**：旧会话规则保留可恢复，再刷新/应用；不要求配置启动参数。新旧包分开保留，最多三个按模块分别计数；本次线上只有一个旧正式版，不需要删除旧 Release。完整包不上传 GitHub。
