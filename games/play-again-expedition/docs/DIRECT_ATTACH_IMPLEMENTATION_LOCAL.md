# 正常启动游戏后的直接接入（本地 0.0.3）

## 目标与范围

Steam 或原启动器正常启动游戏后，主程序连接现有游戏实例，材料、大转盘、掉落页面直接刷新和修改。不再要求用户配置参数、退出重开或使用另一个启动入口。本次只改远征模块，不改宿主、不提交、不发布。

只支持已经验证的 0.116.70 EXE / ASAR / 启动器组合；PID、临时目录、处理函数地址都在本次连接时重新解析。未知构建拒绝执行，不靠版本号相近放行。材料的守关模式限制和原生保存校验保持不变；概率规则仍只作用于本次游戏会话。

## 接入设计

1. 复核选中进程启动时间、进程组、主进程角色、EXE 和 ASAR 指纹。读取目标运行时自行发布的 `node-debug-handler-<PID>` 映射。
2. 处理函数必须落在目标 EXE 的已提交、可执行、非 guard 的 MEM_IMAGE 页面；调用运行时自身提供的处理函数，不猜地址、不分配代码、不写进程内存、不注入 DLL、不关闭安全保护。
3. 用本地独占文件租约串行化不同主程序副本的接入、请求和清理。记录以 PID + 启动时间派生的实例键，拒绝遗留的未确认激活/清理，避免旧实例记录套到新游戏。
4. 只识别两个已知回环端口：普通运行时默认 9229，以及历史临时接口 59321。请求前验证监听者是本次目标主进程，且只监听 IPv4 回环；同时检查 IPv6 占用。不通过代理、不跟随重定向，不向未知端口发送请求。
5. 已有目标接口可以借用，但绝不关闭借用接口。没有接口时先确认默认端口空闲，再调用运行时处理函数。目标只支持默认端口激活；如果端口被其它程序占用，明确报告并停止，不误连、不关掉其它程序、不声称支持任意空闲端口。
6. HTTP 发现和 WebSocket 目标必须是唯一 Node 主进程目标、回环地址和合法 UUID 路径。每次只发送一条内嵌固定业务请求，不开放任意脚本编辑。
7. 写入票据在本地验证和接口发现完成后、唯一一次业务发送前落盘。超时或业务回执不完整不重发，原有 uncertain 状态继续阻止后续写入。
8. 只清理由本次模块启用的接口。清理请求再次核验目标身份和目标 URI，安排运行时在响应和正常断开后关闭接口；持有租约直到监听端口确实消失。清理有界等待，失败记录隔离状态。已确认的业务结果不因后续 WebSocket 断开/接口清理失败变成“没有执行”，也不重发写入。
9. 诊断只检查构建、已发布的处理函数和端口条件，不启用接口、不运行游戏脚本。三个页面只保留简短使用说明，删除“连接准备 / 重启”按钮及旧启动器代码。

## 验证计划

- 模型、权限、票据、并发租约、端口占用、IPv6 占用、非法地址、未知构建、WebSocket 错误、确认后断开失败。
- 实际宿主协调读写路径、三个页面、五种主题和实际 DLL / manifest 加载。
- 通过正式 DLL 在原本正常启动且没有调试启动参数的同一游戏进程上，重复读取、自动启用和关闭接口；验证进程启动时间未变。
- 实际概率总加成小值测试：只临时增加 0.1 个百分点，核验最终原生 getter，再恢复原值；不抽奖、不战斗、不覆盖存档。材料若当前不是守关模式，应证明拒绝发生在写入前，不更改模式或数量。
- 构建新本地目录，在真实宿主中装载三个页面；不覆盖用户当前应用目录。保留测试日志、包哈希和验收边界。

## 编码前三轮复核

### 第一轮：方向与用户体验

普通启动后直接接入原游戏才是目标，不能用自动重启替代直接连接。端口冲突只是安全失败边界，不引入常规启动设置。材料、大转盘、掉落的名称、字段策略和主题资源保持不变。通过。

### 第二轮：对象与生命周期

PID 复用、处理函数映射、监听者、URI、实例票据分别验证。跨副本串行化；已有接口与模块创建接口明确区分；清理期间不释放租约。激活结果不确定不能重复调用。通过。

### 第三轮：真实效果与失败语义

只读诊断不能偷偷启用接口；业务结果确认与连接关闭分离；失败不重发。实机检验最终 getter，而非仅配置值回读。现有材料模式边界不冒充新增支持；旧崩溃报告不宣称已确定根因。验收仅限实测构建和证据。通过。

## 编码后复核与结果

### 第一轮：代码、协议和回归

最终 Release 编译 0 警告 / 0 错误；模块专用 C# 测试 206 项通过，实验目录 Node 测试 316 项通过。新增覆盖跨副本文件租约、PID 复用、非法端点、IPv4 通配监听、IPv6 监听、无效端口、未知运行时，以及成功响应后服务端中断仍返回原成功结果。原三个页面的输入、协调读写、取消/过期/失效回执、宿主主题和实际加载继续通过。DLL 内不再存在旧启动器或连接准备窗口。

### 第二轮：正式 DLL、正常启动实例和真实消费者

在原本从正常入口启动、没有 `--inspect` 参数的同一 0.116.70 主进程上执行正式 DLL：先证明确实拒绝由测试进程占用的 9229 端口，且不关闭该监听者；随后完成 10 轮大转盘 + 掉落读取（共 20 次业务请求），每次临时接口均关闭，游戏实例未变。只读诊断没有开启接口。该模式 38 项检查通过。

材料读取在当前 journey 模式按已有限制拒绝，没有修改材料或强行切换游戏模式；本轮不声称重新完成 29 项原角色持久化测试，历史保存 / 重启证据仍按原范围保留。

正式 DLL 小值配置把 `equipmentBonusPercent` 设为 0.1，实际调用原游戏 `engine.dropBonus()`，观察 **0.011 → 0.012 → 0.011**。只清除仍属于本次测试且 scope / revision 没变的配置，确认掉落及大转盘都回到原规则。完整复测 14 项通过，原生保存内容哈希前后一致、差异路径为空；模块回执确认未调用游戏保存、战斗或抽奖。

首轮小值测试同样确认 getter 修改和恢复，但因保存哈希不一致而判定失败；当时只返回哈希，不能反推出变化字段或把原因确定为自然收益。后来补充只在测试进程内存中比较保存内容，禁止把正文输出或保存到文件，并增加已确认小值测试配置的异常恢复保护，再完整复测通过。保留首轮失败，不能表述成首次即全通过，也没有用旧备份覆盖当前进度。测试辅助代码一次编译发现引用了不存在的 `Values` 属性，改为比较完整规范化配置后重新编译及回归。

### 第三轮：界面、交付和边界

模块测试实际渲染三个页面、五种宿主主题。人工查看浅色大转盘与深色掉落渲染图：连接准备入口已消失，按钮和提示保留宿主风格，未新增自定义颜色。最新使用说明已替换旧流程，历史文档明确标注适用版本，不抹掉旧失败或验证范围。

本地包已在全新目录生成，沿用已有核验的宿主 0.5.1，实际宿主页面验证器通过所有预装模块和本模块三个页面；DLL / manifest 0.0.3、Host API 8、内容 ID 与启动检查均通过。交付结果保存在包旁 `local-package-receipt.json` 与 `module-page-verification.json`。原主进程启动时间仍未改变、仍无调试启动参数，9229 / 59321 均无监听。不更新服务器目录或 GitHub 发布，不覆盖原用户安装或游戏库。

### 未扩大承诺的边界

- 精确构建限制、守关材料模式限制和概率会话策略不变。
- 9229 被其它软件占用仍安全失败，不宣称运行时支持任意端口激活。
- 强制结束主程序发生在启用与清理之间，可能留下隔离记录，需要异常会话恢复；正常请求自动清理。借用接口不由模块关闭。
- 先前一次 InspectorIo 崩溃的根因未完全确定；本次循环和小值测试没有发生崩溃，不等于证明不存在任何运行时缺陷，也不关闭 CFG 保护。
- 新矿区、奶牛关、火焰完整实战等仍按原隔离消费者证据报告，不假称已用原角色逐项实玩。
