# 再刷一把：远征 · 0.0.5 材料状态修复

## 问题与真实依据

0.0.4 的材料运行时在读取前要求 `engine.mode === 'guardian'`，请求组装器再次写死该值。正常选择关卡会将此内部活动标记改为 `journey`，即使 `phase === 'idle'` 也被拒绝。错误提示又要求玩家寻找“守关模式”，因此不是玩家在战斗，也不是单纯文案问题。

使用精确匹配的原 ASAR（SHA-256 `5A4F4E414BD06FC248CFE2AD30E7D9EE3B110968DB888FDB733CD57F78A6B294`）和同版本独立 Electron/Node 运行时只加载纯 Engine。在既有历史保存样本的隔离副本中调用原生 `select`，结果为 `journey / idle`，材料对象仍是原对象。另对八种内部活动标记进行保存/重载比较：保护卷只改一个字段，其他序列化字段不变，恢复成功。这是纯引擎数据路径依据，不冒充八种场景逐一实战测试。

## 详细实施方案

1. 删除材料运行时及请求组装器的固定活动值限制。材料按当前存档的 `state.materials`、普通招募券、深渊挑战券原语义路径定位，不切换游戏状态，也不要求玩家寻找“模式”。
2. 内部活动标记只作为读写期间的上下文一致性校验：验证有限长度字符串并与读取回执比对，不作为特定活动准入名单、不显示给玩家。当前活动、对象或存档若在读写之间改变，要求重新刷新，不自动重试。
3. 保留构建指纹、原进程、唯一有效存档、数量范围、目标字段白名单、同值零写、单次同步赋值/保存、整个序列化对象差异和其他存档核验。未知构建或材料结构仍拒绝，不能通过放宽界面而绕过身份安全。
4. 已进入存档即可只读列出材料。修改时根据实际状态判断：战斗进行中、暂停但战斗未结束、其他操作处理中、转盘动画/奖励待结算、保存被阻止、实时/保存数量不一致分别提示具体原因。对应行保持只读，不把所有原因混成“请停止战斗”。
5. C# 提示映射与材料页面说明同步，旧模式错误的兼容文案也不要求玩家切换隐藏状态。原大转盘、掉落和滚轮布局不改。
6. 新增运行时与控制器回归：多个活动标记、未知但合法标记、标记变化、正常空闲、战斗/暂停、其他结算、保存异常、非法数据以及数量未变不保存。真实引擎隔离副本覆盖 29 项材料在多个活动标记下赋值/重载/恢复，另外核验原生选择关卡路径。
7. 正式 DLL 在当前正常启动的原游戏上只读核验材料与三页。不修改原角色数量、不调用原游戏保存、不替用户切关卡。临时接入复用既有已验证实现，请求结束后核验清理，不建立测试进程的 TCP 监听、不改防火墙。
8. 模块清单与程序集增至 0.0.5，主程序仍为 0.5.1 / API 8；生成全新本地副本，真实宿主加载/启动和 ZIP 哈希校验通过后交付。不提交、不发布，不覆盖旧目录、原安装或游戏库。
