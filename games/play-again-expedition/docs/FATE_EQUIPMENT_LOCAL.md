# 命格概率与装备词条研究（本地，不发布）

## 需求与证据

新增命格抽取各品质概率；装备只在可证明合法上限、最终消费者和原生持久化时提供选中已穿戴装备的一键满值。不得给主程序加入远征专用字段。

2026-10-11 正常 Steam 启动的 0.116.92：Electron 主进程和渲染进程重新定位；无 inspect 参数。使用同版原生 Engine 的独立对象、只读历史研究 fixture，不导入 main/preload，不写原存档。

命格配置为蓝色 70%、紫色 25%、不朽 4%、神话 1%。`rollFate`、`rollFateTen` 共用 `samplePaidFates → sampleFate`。十连正常扣除 10 个不朽碎片，保留候选选择；百抽保底通过第二参数强制神话。调整普通随机品质，保留游戏保底和角色有效池，不修改命格战斗触发概率。

装备 `affixBounds(key, quality)` 确认可读取部分基础数值范围，独立序列化/重新构造可保持普通 value 满值。但是泰坦之力同时含 value 与 value2；装备强化、远古 boosts 又通过 effectiveItem 派生显示数值。单独基础 value 上限不代表所有数值的最终上限，更不代表角色战斗/保存流程已验证。因此不提供“现有装备一键满值”写入 UI；随后按用户追加要求，改为实现下文的新装备生成规则，不把两个功能混为一谈。

## 实施方案

1. 保留材料、大转盘、掉落，新加独立“命格”页面；四档输入 0～100%，合计必须 100%，支持小数，显示原概率。刷新、应用规则、恢复原规则沿用宿主主题和协调读写接口。
2. 独立 FateSession 注册表和当前 Engine 上的 sampleFate 包装，不修改原型、全局 RNG、游戏文件、命格定义、存档或已有候选。正常调用期间临时包装当前 engine.rng，finally 恢复。只映射经当前原生隔离对象发现的品质 RNG 消费点；同档具体命格的随机选择保留，强制神话保底直接走原函数。
3. 当前游戏包的四档配置从原生纯数据模块读取；验证档位顺序、概率总和，现场隔离抽样核验品质消费点，不按旧版文件 hash/列号限制小更新。发现结果只约束命格功能，不影响其它编辑器。
4. 固定 inspect/configure/reset 请求，不接收任意代码；读取回执关联实例/当前存档身份，配置操作只增加本模块规则修订号。刷新不抽原角色、不扣原材料、不保存。正常原游戏进程无需参数；临时入口走已有模块内连接及清理流程。
5. 百抽神话保底仍有效，因此四档百分比指普通抽取，保底抽取不受设置覆盖。应用/恢复不重置保底进度、不撤销合法奖励，也不恢复其他页面规则。游戏重启恢复原概率。
6. 将模块版本从本地 0.0.7 增至 0.0.8；同步 manifest、DLL、说明和测试。复用已核验主程序 0.5.2，输出新名称完整离线 ZIP，保留全部四个游戏模块；不提交、不发布、不修改服务器目录。

## 写代码前的三轮检查

1. 方向：只新增命格概率，不假装实现装备全部满值；主程序零专用改动，正常游戏无新启动要求。
2. 游戏语义：单抽/十连共享采样点，角色限定、材料扣除、已有候选选择和百抽保底继续由原生代码执行；不改 combat 命格触发概率。
3. 生命周期与验证：独立注册表、当前实例绑定、临时 RNG finally 恢复、第三方包装不覆盖、只读读取与复制对象抽奖分开；验证测试覆盖概率边界、十连、保底、恢复、跨编辑器共存与打包实物。

以上三轮完成后开始实现。代码后的三轮检查和离线包证据见本文后续记录。

## 用户追加：在装备生成时取满值

用户要求继续调查生成公式，而不是就此放弃。原生 `makeItem(key, tier, quality)` 已确认：普通数值由 `rollAffix` 取值，专属数值由 sheet-affixes 的 `roll` 取值；泰坦之力的两项分别使用原生 roll。最高合法 RNG 输入可生成 value=5、value2=5；随机选择词条和词条数量使用其它消费点。

追加方案：新“装备”页面仅提供“新生成装备词条取满值”的会话开关；不改旧装备。包装当前 Engine 的 makeItem，仅对隔离原生对象重新发现的两个数值消费点返回最大合法随机值，其余 RNG 照常消耗和返回。词条类型、数量、装备品质、掉落概率和强化/远古后续计算保持游戏规则。恢复只卸载本开关，不撤销已经得到的装备。

追加方案三轮检查：

1. 需求边界：这是新装备生成规则，不冒充旧装备一键修复；不会主动制造/发放装备或修改现有装备。
2. 原生公式：让原生函数计算上下限，包括第二数值；不修改配置、不统一写任意上限、不更改选词条 RNG。
3. 隔离和共存：只在 makeItem 的同步调用内暂时接管 RNG，finally 恢复；与大转盘、掉落、命格独立；测试原生生成、默认等价、合法范围、重载、其它随机消费、异常恢复和规则共存。

三轮完成后实施此追加方案。
