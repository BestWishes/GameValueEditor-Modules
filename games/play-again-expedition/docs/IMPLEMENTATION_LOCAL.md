## 详细方案

1. 新模块 `game.play-again-expedition`，本地版本 0.0.1，Host API 8 / 主程序最低 0.5.1。两个内容模块稳定 ID 为 `.materials` / `.lucky-wheel`，显示名称严格为“材料”“大转盘”。模块自己创建 WPF 页面，主题颜色、字体和控件样式继承宿主。
2. 材料：直接展示 29 项材料的名称、分类、实时/保存数量、范围与可写状态，支持搜索、刷新、单项修改和保存语义快捷字段。不做批量赋同值、自动写入或材料锁定。调用已验证的单叶子原生保存和完整差异核验路径。
3. 大转盘：五类奖格百分比（合计 100%）、double / marquee 额外奖励百分比（合计不超过 100%），可选类内类型/品质权重。先编辑整份配置，点击“应用概率”才通过宿主协调桥写入；“恢复原概率”走同一语义队列。显示实际 16 格分布、当前是否已应用；不代用户抽奖、不改价格/奖品池、不永久保存概率、不重启自动应用。
4. 将已验证 JavaScript 固定请求在构建时嵌入 DLL。运行时用 C# 回环协议，不依赖外部 Node、PowerShell、小工具或测试副本。可分发包严格只有 DLL 与清单。
5. 每次按当前选中逻辑进程组重新定位原游戏主进程、实例和 EXE/ASAR 指纹；非 Steam 入口同样可用，不固定盘符。支持模块在未开启接口时被识别，页面显示启动参数说明；不强行开启 inspector、修改安装、启动选项或存档。操作需要用户明确使用 `--inspect=127.0.0.1:59321` 启动已验证原游戏。
6. 精确验证回环监听所有者、单一 browser_init 目标、原窗口/隔离世界/存档/引擎，固定 JSON 输入、旧值/revision、持久互斥和不确定操作屏障。未知构建、正在战斗、未进入存档、pending 抽奖等安全拒绝；关闭客户端，不关闭 inspector 服务。
7. 完成源码与页面回归、嵌入请求和后端回归、实际宿主包加载、主题/生命周期/错误检查，再生成本地包。使用独立本地安装目录，不覆盖现有已发布安装、用户库或模块。记录未重新实机验收的边界，最终执行不带强制关闭参数的正常关机。

## 编码前检查三遍

1. 方向/范围：只有两个指定页面；材料持久化、概率会话化分开；分类百分比和类内权重不能混淆。没有额外掉率、角色属性、批量材料或自动抽奖功能。
2. 安全/可移植性：原入口不要求 Steam；完整 EXE + ASAR、逻辑进程组与启动实例不可被名称/旧 PID 替代；固定请求嵌入程序集，无外部脚本运行依赖。显式接口不可用时说明原因，不能偷偷恢复曾崩溃的强制接口路线。
3. 集成/验证：所有页面写入与整页读取分别使用 API 8 协调桥；模块自行决定布局但不定义主题。概率整体配置只能通过一个会话语义目标，不允许各百分比分开提交造成暂时非法总和；取消/失效/错误不写入，未知版本不启用。已有实机证据只对精确 0.116.70 有效。
