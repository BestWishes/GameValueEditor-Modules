## 游戏声明信息（只读）

此能力包含在正式模块 `1.0.4` 和此前本地模块 `1.0.3` 中，不代表历史公开 `1.0.2` 包具备此能力。

模块实现宿主既有的 `IGameVersionMetadataProvider`，供“游戏版本”页和兼容性诊断显示。当前构建保留 `UnityEngine.CoreModule.dll` 中 `UnityEngine.Application.get_version` 的静态、无参数、`System.String` 返回值方法；名称的托管 getter 已被裁剪，不能照搬其他游戏的 getter 组合。实际读取路径为：

- 游戏声明版本：运行时 `Application.get_version()`。
- 游戏声明名称：同一安装目录的 `Deskrawl_Data/app.info` 第二行产品名。
- 游戏构建 GUID：同一安装目录的 `Deskrawl_Data/boot.config` 中唯一、合法且非空的 `build-guid`。

三个值保留游戏自身的声明，不翻译产品名，不以模块清单、EXE/引擎版本或平台构建号代填。读取不依赖人物或存档加载，不安装主线程/规则钩子，也不调用刷新或保存方法；仍核对进程实例与加载路径。启动文件仅按有界 UTF-8 文本读取，单个文件缺失、不可读、内容无效或 GUID 重复时只留空该项，不丢弃其余信息。运行时读取失败沿用宿主可选元数据的失败处理，不阻止已支持构建连接；实际值为空时仍显示“未提供”。声明信息不代替运行时结构验证。

`--metadata-only` 实机入口仅验证这些声明信息、连续读取一致性和过期进程实例拒绝，不执行原有实机测试中的人物覆盖、规则切换或物品写入。变更/缺失指纹的自动识别由 `--compatibility-only` 验证。

2026-10-15 原游戏只读实测：声明版本 `1.0.2b`，声明名称 `Deskrawl`，构建 GUID `f2cada4bfd87488386b534169e539aac`；连续读取一致，过期进程实例与未知构建均被拒绝，测试前后活动存档的 SHA-256、长度及修改时间均未变化。文件异常的独立回归入口为 `--game=deskrawl-metadata-files`，只创建并清理临时测试文件，不连接游戏。

## 六个编辑器及写入边界

### 人物属性

| 字段 | 权威读取 / 写入 | 生命周期 |
| --- | --- | --- |
| 金币 | `PlayerData.Gold`；按与当前值的差额调用游戏金币入口 | 请求 `SaveSystem` 保存 |
| 当前经验 | `Player.CurrentXP`；保留当前等级并调用游戏经验装载入口 | 请求 `SaveSystem` 保存 |
| 可用天赋点 | `PlayerTalentBook` 独立余额和增量入口 | 请求 `SaveSystem` 保存 |
| 可用巅峰点 | `hh` 巅峰等级、已用点、可用点和每级点数 | 换算合法巅峰等级并请求保存 |
| 基础主属性 | `Player.BasePrimaryStat` | 请求 `SaveSystem` 保存 |
| 力量、敏捷、智力 | `Player.bjy(StatType)` 最终属性消费者覆盖 | 仅本次运行；装备重算不会清除 |
| 金币发现、物品发现、生命药水发现、材料发现、获得经验值 | `Player.bjy(StatType)` 的 15、16、17、19、41；底层小数乘 100 显示 | 仅本次运行；最终消费者覆盖 |

天赋点和巅峰点是分开的。当前构建每个巅峰等级发放 1 点；游戏不单独保存一个任意的“巅峰点余额”，所以模块保留已经分配的点数，把目标可用点换算为巅峰等级，并拒绝不能由每级点数整除的目标。金币发现、物品发现、生命药水发现、材料发现和获得经验值在游戏面板中都是百分比；旧版直接显示底层小数会错 100 倍，本版统一按 `底层值 × 100` 显示、按 `输入百分比 ÷ 100` 写入。

### 装备生成

游戏生成装备词条时先按属性类型和物品等级得到基础值，再使用 `Random.Range(0.85, 1.15)` 生成随机倍率，并叠加稀有度系数。当前构建的该段稀有度增量观察为普通 `+20%`、优秀 `+40%`、稀有 `+50%`、传奇 `+60%`；不同词条随后还会按自身规则舍入，最小值不低于 `0.001`。

“启用最高值”只把装备词条生成函数中这一次浮点随机调用替换成它自己的上界参数，即固定为 `1.15`。它不会修改全局随机数，不会回改已有装备；解析位置不唯一、原始机器码不匹配或检测到其他工具改动时会拒绝接管。关闭开关或离开页面时恢复原始代码。

### 掉落规则

#### 怪物装备掉落率

普通、精英、小头目、头目和神话头目各有 `MinLootVector` / `MaxLootVector`。每个向量由 `NoDrop`、`Common`、`Uncommon`、`Rare`、`Legendary` 五个权重构成；抽中 `NoDrop` 时本次尝试不生成装备。页面设置的百分比只反算十个向量的 `NoDrop`，保留四种装备稀有度之间的原始比例，也不改变各怪物的 `RollAttempts`。

设置范围为 `1%～100%`，表示每次装备掉落尝试的非空概率。怪物可能有多次尝试，所以它不是“每只怪必定只掉一件”的数量开关。

#### 离线可交易特殊掉落倍率

`LootManager.duh()` 返回离线规则下的 `LootConfig.OfflineTradableDropMultiplier`（某一存档模式固定返回 `1`）。调用路径分析确认，稀有鱼候选及部分特殊物品会使用该倍率，而且这些路径没有读取人物 `MagicFind`。因此本版不再把它冒充“物品发现”，而是在掉落规则页以“离线可交易特殊掉落倍率”独立提供；`100%` 表示 1 倍候选权重。

人物“物品发现”保留在人物属性页，权威消费者为 `Player.bjy(StatType.MagicFind)`；它参与普通装备稀有度权重计算，但不会替代上述独立特殊路径。

### 钓鱼

原生成功率通过地图 `NothingChance` 与钓鱼技能 `SuccessBonus` 计算。技能加成大于零时：

```text
调整后空钓率 = max(0, 1 - (1 - 地图基础空钓率) × (1 + SuccessBonus))
最终成功率   = min(1, 地图基础成功率 × (1 + SuccessBonus))
```

页面提供 `0%～100%` 的最终成功率覆盖；恢复后重新使用各地图和技能的原始公式。对 `PlayerFishingController` 的最终入库路径检查表明，每次成功固定调用背包入口加入 `1` 个物品，当前构建不存在独立的“钓到数量”倍率，所以模块明确显示这一结论而不提供无效控件。

钓鱼成功率为本次运行的规则覆盖，不写入存档；页面关闭时自动恢复。人物物品发现不放在钓鱼页。稀有鱼使用的离线特殊倍率在“掉落规则”页设置和恢复。

### 材料

材料定义来自游戏加载的 `SaveSystem` 物品定义表，仅保留 `ItemData.Type == Material`。稳定键始终使用资源名；显示名称则在 Unity 主线程调用 `ItemData.ceu()` 获取当前中文本地化文本，身份与显示分离。

数量由 `Inventory.fcs(ItemData)` 权威读取。减少调用游戏消耗入口，增加调用游戏入库入口，因此数量为零且没有库存行的材料也能由游戏正常创建；成功后请求保存并按资源名重新读取。当前构建发现 30 种材料，实机验证全部显示中文，例如 `TreasureMapKey → 白银宝藏钥匙`、`ore1 → 铁矿石`、`SoulShard → 灵魂碎片`。

`Inventory.fcp(ItemData)` 返回携带上限而不是当前数量；模块只用它约束合法最大值，不再把它误作库存读数。

### 背包物品

“背包物品”从同一完整定义表中识别非材料且 `MaxStackSize > 1` 的定义，当前构建共识别 67 种可堆叠定义；页面只显示 `Inventory.fcu(ItemData) > 0`、即当前实际拥有的物品。显示名同样由游戏本地化方法读取。数量为零的定义、不可堆叠的宝箱和装备不会出现在列表中。

增加和减少分别调用游戏 `Inventory.fcb` / `Inventory.fcv`，写入前核对旧值，成功后请求 `SaveSystem` 保存并重新读取。界面只列出可堆叠物品，不把装备等非堆叠实例误当成数量字段。

## 线程、并发与失败边界

- 所有会改变 Unity/IL2CPP 对象或读取本地化资源的方法都排入 `UnitySynchronizationContext` 主线程。
- 写入在一次主线程动作中读取旧值、计算差额、调用游戏入口并读回；旧值已变化、游戏拒绝、回读不一致时均不报告成功。
- 页面通过 Host API 8 的字段协调接口执行写入。持久字段和仅本次运行的覆盖字段都不允许宿主周期锁定。
- 主线程入口操作由进程内共享门串行执行，避免材料/背包本地化刷新和人物写入同时占用入口。可堆叠物品兼容诊断只检查定义与字段，不安装本地化读取钩子。
- 兼容诊断按核心运行时、人物属性、装备生成、掉落规则、钓鱼、完整材料、可堆叠背包物品和保存链分别执行；缺失哪一项就停用哪一项。
- 模块只接受唯一的 `Deskrawl` 进程；多实例、进程退出或语义解析不唯一时安全失败。

## 保存与恢复

游戏活动存档为安装目录 `Data/save.json`，文件头为 `DDS2`，由游戏自己的加密与认证保存链维护。模块不直接解密、编辑或替换存档文件；持久字段、材料和背包物品均调用 `SaveSystem` 正常保存入口。

实机写入前应为活动存档制作单独的只读恢复副本并记录 SHA-256、长度和时间。恢复副本只能在游戏完全退出后人工替换；运行中的模块不会用文件覆盖游戏内存状态。

## 已知限制

- 最终人物派生属性是会话覆盖值，不持久化；当前构建通过最终消费者覆盖避免装备重算清除，实际战斗/结算效果仍应在游戏内做受控对比。
- 装备最高值、掉落规则和钓鱼成功率是本次运行的规则覆盖，不持久化；关闭对应规则页面会恢复。
- 人物物品发现只调整普通装备稀有度权重，不等于必出装备或增加数量；当前构建没有独立钓鱼数量参数。
- 巅峰可用点由巅峰等级和已分配点推导，目标必须符合游戏每级点数档位。
- 上表写入/持久化证据来自原始分析构建，不能冒充更新后的游戏效果实测。1.0.3 本地模块允许未登记指纹进入实际结构验证；代码或布局变化超出已验证语义契约时，安全拒绝受影响能力，不承诺任意未来版本兼容。
