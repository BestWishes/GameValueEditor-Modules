# 小更新自动识别修复与本地交付 1.0.3

## 根因与强制规则

旧版存在两层独立问题：`Supports`/诊断先按旧三文件指纹整包拒绝；绕过该判断后，游戏更新重新混淆方法名和类型别名，`dkg`/`edw` 等名字失效，仍无法定位。这不是 Steam 与非 Steam 身份可以单独解释的问题。

现在遵守两仓 `AGENTS.md` 和扩展指南的强制契约：未知指纹进入本地只读验证；实际结构不相容则拒绝受影响功能。清单、模板、`validate-modules.ps1` 和发布验收共同禁止当前官方模块关闭自动验证。历史发布资产/目录快照不改写，本地包不等于公开发布。

## 语义定位与边界

`semantic-mapping-103.json` 记录原始角色与当前候选对照，不包含运行期地址。旧混淆字符串仅作为内部历史角色键，不是运行时方法名。`Compare-SemanticDumps.ps1` 只读取明确指定的两份分析输出；生成的研究映射不自动成为交付契约。

生产契约在 `src/semantic-contracts.json`，嵌入 DLL：按所属类型、静态性、返回/参数类型筛选，再验证整个已分析函数的规范化指令摘要与唯一性。保留字段位移、立即数、操作宽度和函数内跳转目标，仅抹去模块重定位地址；不是短序言、同签名或固定 RVA。当前/原始已审查的五处差异分别保留契约，不把所有偏移通配。混淆类型别名只是已观察候选提示，失败时在有上限的游戏元数据类型集合中查找，禁止按相邻名字/序号推算。材料定义字段按唯一字典类型与完整定义内容验证，不依赖已变化的混淆字段名。

每次操作校验进程实例/加载路径；方法缓存绑定进程启动、模块映射、文件状态和契约。人物、装备、掉落、钓鱼、材料、可堆叠物品与保存链独立检查。根结构失败拒绝连接，业务结构失败拒绝该入口。兼容诊断不安装业务钩子，不刷新或保存。元数据查询使用既有 IL2CPP 查询机制；“只读”指不执行业务修改，不等于不使用临时查询缓冲区。
