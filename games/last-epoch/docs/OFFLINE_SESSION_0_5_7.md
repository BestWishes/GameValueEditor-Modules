# Last Epoch 0.5.7：两种离线入口

## 范围与方案

2026-10-12 用户授权正常客户端离线角色适配、提交和发布。只改 `game.last-epoch`，Host API 8、最低宿主 0.5.1、五个页面和语义键不变；宿主 0.5.3 不重发。小更新仍按当前元数据定位，不恢复旧哈希白名单。指纹只记录测试来源。

正常入口只读研究确认：命令行没有 `--offline`；`EHG.Multiplayer.GameplayEnvironment._isOnlinePlay` 为 false，`IsServer` 为 false，而 `IsOnlinePlayDefault` 为 true；`PlayerFinder.localPlayerDataTracker.charData` 和人物 Actor 已加载，`LE.Data.CharacterData.get_IsOffline` 的原生 bool 返回值为 true（只取 AL，不将 RAX 的未定义高位当 bool）。角色的 `_isOffline` 是 nullable 缓存，不能将缓存未赋值误判为联机。

1. 按当前游戏状态而非启动参数确认离线。通过当前 IL2CPP 导出解析上述静态 bool、人物根及离线 getter。完全离线和普通离线采用同一判断；默认联机开关、互联网连接和聊天连接不作为拒绝条件。
2. 状态分别为离线角色已加载、联机游玩、未进入角色、状态无法读取。诊断将运行状态与人物根结构分开，未执行的结构检查不能宣称失败。未知状态不伪称联机。读取版本声明不要求角色已加载。
3. 每次读写绑定当前角色对象。写入及游戏主线程一次性修改再次检查；角色变化时取消旧操作，不能通过旧页面或保存字段继续修改新角色。
4. 经验、物品掉率和金币数量的原生钩子增加当前离线状态和角色对象门闩。门闩在游戏自己的调用时执行，非宿主定时检查；不符时只走原游戏逻辑。新角色不继承旧倍率，需在当前角色重新应用。不在线修改钩子正文；只更新自有钩子数据。旧版未加门闩钩子不重写、不叠加，需重新启动游戏清除。
5. 验证真实普通离线入口、五页读取、可逆小值修改，并明确区分读取、即时修改、存档持久化、隔离原生门闩测试。同步模块文档，三遍代码检查后从干净提交打包。先资产校验，再目录发布，最多保留三版正式 Release，历史标签保留。

## 写代码前三遍方案检查

- 第一遍：两种入口、默认联机/实际离线区别、未进入角色、状态读取失败和结构失败的提示，均不要求用户配置参数。
- 第二遍：窗口切换不是游戏角色切换；旧角色指针、宿主持久锁定、原生倍率钩子、一次性主线程操作及已有旧版钩子分别审查。钩子必须在游戏内拦截，而不能只在按钮点击时拦截。
- 第三遍：模块/宿主边界、当前元数据重新定位、版本 0.5.6→0.5.7、Host API 和页面不变、不可变资产/目录后置/三版保留。发布 skill 的构建身份核验用于记录来源，不覆盖用户批准的当前元数据动态适配策略。
